## 一、產品願景與問題陳述

現代人在高壓的工作與學術環境下，常需要片刻的喘息空間，但尋找這樣的空間往往伴隨著摩擦：
1. **資訊過載與決策疲勞：** 打開地圖 App，面臨上百個星級評分，難以判斷哪個符合「現在的心情」。
2. **群體決策的社交壓力（責任分散效應）：** 和朋友聚會時，「今晚吃什麼」成了一個沒有人願意承擔責任的問題。

**「慢活靈感指南」**旨在打造一款無壓力的探索與決策工具。我們不追求「最高 CP 值」或「最多人打卡」，而是專注於**「氛圍契合度」**與**「零摩擦的社交決策」**。

---

## 二、核心解決方案與功能

本專案圍繞著三個核心體驗模組打造：

### 1. 尋找避難所 (Vibe Match) - 氛圍契合度推薦
> **痛點：** 我不想看排行榜，我只想找個安靜的地方寫程式。
**解法：** 拋棄傳統的分類（如：日式、義式），改以「心情標籤（Mood Chips）」驅動。系統根據使用者當下的感受（如：適合一個人看書、安靜、老派浪漫），精準比對出契合度最高的地點。

### 2. 佛系揪團 (Pass-and-Play) - 零壓力的群體決策
> **痛點：** 聚會時沒人想決定去哪吃，怕選到雷被嫌。
**解法：** 「你負責聚，我負責選。」
- **盲測投票：** 將手機遞給下一個人，每人獨立對隨機選項按 ❤️ 或 ✖️，消除群體從眾效應。
- **系統承擔責任：** 計算交集，若平手則由亂數決定。加上 3-2-1 開獎與紙花儀式，把煩人的決策變成一場歡樂的命運抽籤。

### 3. 探索護照 (Visualized Journey) - 療癒的足跡紀錄
> **痛點：** 單純的清單打卡缺乏情感連結與成就感。
**解法：** 結合在地化的插畫與視覺回饋。隨著使用者造訪次數的增加，手繪的美食地圖會逐漸豐富，從線稿變成充滿細節與色彩的完整畫作，將探索過程視覺化。

## 三、技術架構與設計決策

### 技術棧選擇
| 技術 | 選擇理由 |
|------|---------|
| **Blazor WebAssembly** | 純 C# 開發，編譯為 WebAssembly 於瀏覽器本地執行，不需後端伺服器 |
| **MudBlazor** | 提供精緻的 Material Design 元件，實現高質感的 Glassmorphism（毛玻璃）視覺風格 |
| **LocalStorage** | 取代資料庫，使用者的探索護照與足跡永遠保存在自己的設備上，確保隱私 |
| **GitHub Pages + Actions** | CI/CD 自動化建置與部署，實現零維護成本的高效發布 |

### 核心設計理念：零門檻與高隱私
本專案堅持 MVP 的極簡原則：
- **不需下載 App：** 掃描 QR Code 即可使用。
- **不需註冊登入：** 消除漏斗流失，Pass-and-Play 模式讓一群人只要一支手機就能完成投票。
- **不收集個人資料：** 所有運算（包含 Vibe Match 演算法與計票邏輯）皆在 Client-side 發生。

## 四、AI 驅動開發範式

本專案全程採用「Vibe Coding」與 AI 輔助開發，涵蓋：
- PRD 撰寫、使用者故事與功能拆解
- C# 演算法（如：標籤相似度計算）實作
- UI/UX 組件設計與 CSS 動畫（紙花特效）生成
- GitHub Actions 自動化部署流程設定

從概念發想到產品上線，展示了 **PM 產品思維 × AI 工具** 深度結合的現代軟體開發效率。

## 五、商業模式與未來展望

| 階段 | 商業模式 | 做法 |
|------|---------|------|
| **v1.0（當前）** | 完全免費 | 建立用戶習慣，驗證「氛圍推薦」與「盲測決策」的核心假設 |
| **v2.0** | 商家精選推薦 | 協助在地質感小店精準觸及目標受眾（如：需要安靜空間的工作者） |

**長期願景：**
從單純的餐飲推薦，擴展為通用的**「慢活決策引擎」**——無論是挑選週末的踏青景點，或是決定今晚的放鬆方式，只要是需要排除資訊噪音、回歸真實感受的場景，都是本產品的發揮空間。
